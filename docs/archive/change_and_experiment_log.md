# 修改与实验记录

> Archived on 13 October 2026. This document records its original stage; dates, budgets and pending work below are historical. Current scope and results: [frozen release](../frozen_release.md), [verification](../verification.md). Commands run from the repository root.

更新：2026-10-13。按“修改了什么 → 为了解决什么问题 → 实际结果”记录主要变化。最初8项是历史记录，不代表8个独立版本或8次对照实验；第7、8项一起测试。第9项为三组对照，第10项为之后的一次训练后评估；历史条目中的“未评估”描述当时状态。文档整理不计作模型优化。

## 1. 首轮静态审查后的运行与安全修复

- **修改了什么：**新增跨运行共享的费用预留账本；等待同组已发出的任务结束后再清理；将可修复SQL错误返回给模型；Snowflake使用managed access schema授予限定权限；分别记录“运行有效、已提交、任务全对”。最终归入提交`9def90c`。
- **为了解决什么问题：**单次预算限制不能防止累计超支；并发任务可能在清理后继续操作数据库；SQL错误被错误地视为基础设施故障；原Snowflake授权流程缺权限；部分正确的有效rollout被误报为运行失败。
- **实际结果：**当时43项本地测试和Lint通过；后续真实Snowflake权限预检验证raw读权限与写入限制。修复了可运行性与记录方式，没有证明模型成功率提高。
- **证据：**`docs/archive/static_review.md`；`runs/static_review_regression_20261009.log`；`runs/snowflake_rbac_preflight.json`。

## 2. 早期模型运行中的提示与参数调整

- **修改了什么：**删除初始提示中重复的任务JSON，保留`inspect_task`的完整任务；增加准确表名及执行指导；生成上限由2048改为4096。4B尝试仍失败后，操作员明确改用Qwen3.5-9B、24576上下文和24轮。代码归入`9def90c`，模型选择属于运行配置调整。
- **为了解决什么问题：**模型输出被截断、重复查询消耗上下文，以及没有完成转换与显式提交。
- **实际结果：**三条4B真实尝试依次因`max_tokens`、`context_overflow`、`max_turns`结束，均未提交、R0。随后9B一条真实rollout提交，R0.8125，匹配13/16列；独立进程重放一致。由于模型、提示和参数都有变化，不能把改善归因于某一项修改。
- **证据：**`runs/official_rollout_20261009_01/`、`runs/official_rollout_20261009_02/`、`runs/official_rollout_20261009_03/`；`runs/official_rollout_20261009_9b_01/`；`runs/official_rollout_20261009_9b_replay/`。

## 3. Tinker训练数据保存与恢复修复

- **修改了什么：**适配SDK dataclass序列化；增加原始真实轨迹恢复入口、独占请求记录和预算检查，防止不确定请求被重复发送。归入`9def90c`。
- **为了解决什么问题：**四条真实轨迹已采样，但保存训练数据时错误地调用`model_dump`，训练尚未发出便失败；直接重跑会浪费采样费用，并可能重复计费。
- **实际结果：**完整复用原轨迹、观察、采样logprobs及执行奖励；奖励为`[0, 0.875, 0, 0.9375]`，优势不全为0。服务确认一次真实forward/backward及优化步骤，checkpoint保存成功；最终46项本地测试通过。新learner是同base/rank的初始LoRA，未声称恢复原client。未评估更新后模型，因此只证明训练链路完成，未证明RL提高准确率。
- **证据：**`runs/tinker_step_20261009_9b_resume_01/optimization_acknowledgement.json`、`training_mask_verification.json`；`runs/final_real_acceptance_tests_20261009.log`。

## 4. v0.2：SQL兼容、日期与执行状态反馈修复

- **修改了什么：**允许受控的`models.<目标表>`写法；支持`FIRST_VALUE`、`EXISTS`及`TO_DATE`的解析器名称；区分SQL策略拒绝；日期使用ISO格式并保留NULL和实际时区；返回实际列类型、加载状态与工具调用余量。提交`1326ab6`。
- **为了解决什么问题：**正常SQL被接口误拒绝；日期以整数显示，增加理解负担；模型无法清楚判断已完成加载及剩余工具预算。
- **实际结果：**该阶段60项本地测试和Lint通过。对原4条真实轨迹的51次transform只做离线策略解析，接受数由32变为43，新增接受11条、没有新增拒绝；这没有执行SQL，不能当作成功率提高。后续人工Snowflake小任务验证这些接口可执行，属于环境预检。
- **证据：**`runs/new_version_20261010/tests_reliability.log`、`policy_comparison.json`、`snowflake_preflight/acceptance.json`。

## 5. v0.2：公开字段覆盖反馈与CI

- **修改了什么：**增加默认关闭的`field_feedback`；成功转换后读取实际输出schema，提示公开要求中的缺列、错名和额外列；添加构建、Lint、无凭据测试及独立重放CI。提交`b204ae2`。
- **为了解决什么问题：**基线已经算出首单重量，却因输出列名不符失分；模型缺少字段覆盖反馈；代码缺少自动验证门禁。
- **实际结果：**与第6项合并后，69项本地测试、构建及干净安装通过，远程CI成功。同一v0.2修复版真实试运行各一次：关闭反馈未提交，因上下文溢出R0；开启反馈提交，R0.9375，匹配15/16列，独立重放一致。唯一错误是`num_shipments_2017`统计了所有年份。各仅一条且未固定seed，不能证明反馈提升成功率；旧版更新前采样也出现过15/16，不是新最高成绩。两轮本地耗时比较方向相反，没有稳定提速证据。
- **证据：**`runs/new_version_20261010/tests_final.log`、`ci_job_114002188058.log`；v0.2 CI run `37984267995`；`runs/v2_paid_test_20261010/REPORT.md`、`on_independent_replay/grade.json`。

## 6. v0.2：明确已创建模型，补空表与重复调用检查

- **修改了什么：**从成功SQL中记录唯一`created_models`；增加空表字段齐全、重复创建同一模型的回归测试。提交`0b1091e`。
- **为了解决什么问题：**成功SQL数量无法说明哪张输出表已经建立；“列齐全”可能被误解为“数据正确”；重复执行可能让进度显示失真。
- **实际结果：**本地验证空表即使列齐全仍R0；重复转换记录2条成功SQL、1个模型，正确结果仍R1。最终69项测试通过。此项与第5项一起进入v0.2付费试运行，没有单独模型对照，不能单独声称改善提交行为。
- **证据：**`docs/archive/review_v0_2.md`；`tests/test_feedback.py`；`runs/new_version_20261010/tests_final.log`。

## 7. v0.3：压缩工具反馈，显示真实模型轮数并提醒提交

- **修改了什么：**增加默认关闭的`compact_feedback`：模型看到的查询预览最多6行、错误最多600字符、紧凑JSON；完整工具轨迹仍保留。反馈增加真实剩余模型轮数，最后两轮提醒显式提交；compact模式将下一轮生成预留由4096改为128，实际采样仍受4096生成上限及剩余上下文限制。提交`14c9123`，未自动提交。
- **为了解决什么问题：**查询反馈使历史持续增长；预留4096生成token会过早触发上下文停止；模型反复查询，耗尽轮数却没有提交。
- **实际结果：**与第8项一起完成76项本地测试、构建、干净安装、独立重放及远程CI。离线重渲染旧失败历史，最终输入从21460降到16232，减少5228 tokens；这是同一历史的模型输入大小比较。最新真实运行没有上下文溢出，最大输入15387 tokens，但到24轮仍未提交，R0，30次工具调用、5559生成tokens。两张模型表已建立，最后仍在查询，最终正确列数未知。没有解决完整提交问题，也未证明相比旧版效果改善。
- **证据：**`runs/context_fix_20261010/offline_diagnosis.json`、`tests.log`、`live_result.json`、`live_01/`。

## 8. v0.3：公开年份条件检查提示

- **修改了什么：**从公开字段描述提取年份，检查SQL AST是否出现对应年份常量；缺失时给出非阻塞的复核提示。与第7项同属`14c9123`，不读隐藏答案、不提供正确SQL、不修改reward。
- **为了解决什么问题：**v0.2提交中把全部记录的`COUNT(*)`命名为`num_shipments_2017`，字段名正确但遗漏2017筛选；字段覆盖无法发现这种语义错误。
- **实际结果：**离线检查旧错误SQL时，能够提示复核2017条件。最新真实运行中该提示触发0次，且没有提交，所以尚无实际纠错效果证据。这个检查可能因间接年份表达式误报，也可能因无关年份常量漏报，不能充当语义正确性评判器。
- **证据：**`runs/context_fix_20261010/offline_diagnosis.json`、`live_result.json`；`elt_tinker/feedback.py`。

## 10. 加载已训练checkpoint，完成一次更新后评估

- **修改了什么：**增加仅rollout可用的`--checkpoint-record`，核对已完成训练记录、模型、rank和provenance，再加载实际训练权重；云端身份不符即拒绝，不回退原模型、不追加训练。训练专用超参数依赖改为按训练/恢复路径导入。
- **为了解决什么问题：**此前入口只能采样原公开模型，无法评估已保存的RL更新；无用的训练依赖和本机WMI/WSL故障阻塞准备。系统修复和五源内容验证全部完成后才采样，故障不计为模型样本。
- **实际结果：**实际checkpoint评估有效，但24轮/30工具未提交，R0；7个原生SQL编译错误、9011生成tokens、177.12秒，两模型创建过但正确列数未知。未显示收益；双方仅单条、训练反馈版本较早，不能推断总体退化。原一次真实优化证据保留，本次新增优化0。
- **证据：**`docs/post_training_evaluation_20261013.md`；`runs/post_rl_eval_20261013/result.json`、`control_audit.json`、`failure_analysis.json`和`cleanup.json`。版本0.3.1冻结说明见`docs/frozen_release.md`。
